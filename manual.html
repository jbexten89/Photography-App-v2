1. Quick Start

1.1 Opening the app

The app is a single web page hosted on Vercel. Open the URL in any modern browser (Chrome, Safari, Firefox, Edge). There is no install. On first open you'll see a sign-in screen (if cloud sync is enabled in Settings → Cloud Sync) or go straight to the Overview page.

1.2 Adding your first transaction

  1. Click Transactions in the left sidebar (or in the bottom-tab on mobile).
  2. Click + New Transaction in the toolbar.
  3. Fill in date, payee, amount (either Inflow for income or Outflow for expense), category, and any optional fields (vendor, customer, memo, tags, chart of accounts).
  4. Click Save.

Allowed values for Outflow and Inflow include $0.00 — the form rejects only the case where both fields are empty.

1.3 Creating a job

  1. Click New Job in the sidebar.
  2. Click + New Job.
  3. Enter date, Job No. (free-form, suggested format YY### like 26001), customer, category (Spring Sports, Baseball, etc.), and optional hours.
  4. Save. The job is now selectable from any transaction's "Existing Job" picker and from the invoice editor.

1.4 Creating an invoice

  1. Click Invoices, then + New Invoice.
  2. Pick a customer (or pick a Job — Bill To and Invoice # are auto-filled from the job).
  3. Add line items: Item · Qty · Description · Price (Amount = Qty × Price).
  4. Pick Tax / Non-Tax. If Tax, choose a rate from the dropdown (7.00% or 7.25%).
  5. Click Save. Click Mark as Paid to stamp the invoice with a green PAID watermark and record the payment date.
  6. Click Print / PDF to produce a print-ready letter-size invoice.

1.5 Backing up your data

Open Settings → Cloud Sync and sign in with an email + password. The app will push any local data to Supabase on save and pull the server-side copy when you open the app fresh. If you want a one-shot snapshot, click Force Upload; if you need to recover the server's copy, click Force Download.

2. App Layout & Navigation

2.1 Desktop layout

Three regions on every page:

  • Left sidebar — vertical list of every page, with the photographer logo at the top, the cloud-sync status pill below it, and the theme/gear icons at the bottom. The active tab is highlighted with the accent color.
  • Main canvas — the page's own UI takes up the remaining width up to a 1400px max. Most pages have a heading, a toolbar (filters, action buttons), and one or more content cards beneath.
  • Right flyout — a duplicate of the sidebar that can slide out from the right edge on narrow viewports, controlled by the "More" button in the bottom nav.

2.2 Sidebar tabs

The full list, in display order:

  1. Overview — dashboard with year totals, year-over-year, and per-job summaries.
  2. Calendar — yearly mini-month grid plus a list of scheduled jobs.
  3. New Job — create job records and view per-job analytics.
  4. Transactions — the full ledger of income and expense entries.
  5. Analytics — ten analytical views in a single page (Year Matrix is the default).
  6. Invoices — list + editor for outgoing customer invoices.
  7. Mileage — per-trip vehicle mileage log and rate.
  8. Reports — printable financial summaries (P&L, Schedule C, Sales Tax, etc.).
  9. Settings — gear icon at the bottom.

2.3 Mobile layout

Below 768px viewport the sidebar collapses. Navigation moves to:

  • A bottom tab bar with the five most-used pages (Overview · Transactions · Calendar · Analytics · More).
  • The More button opens a right-side flyout containing every other tab and Settings.
  • A hamburger icon on the top left opens the original sidebar from the left edge.

Each page has its own mobile-specific layout: toolbars wrap, tables stack into card-like rows, big totals shrink, and charts apply font-size overrides so SVG text reads clearly at phone width.

2.4 Themes

Click the moon/sun icon at the bottom of the sidebar to toggle dark/light mode. The choice persists in localStorage.

2.5 Locked years (preview)

A small red dot in the bottom-right of a year pill (on Overview, etc.) indicates the year is locked in Settings — no edits or deletes are allowed to any record dated within that year. See Locked Years later in this manual for details.

3.2 Transaction shape

Each transaction has:

  • id — unique string.
  • date — "YYYY-MM-DD".
  • type — "income" or "expense".
  • amount — positive Number (sign comes from type).
  • payee — string (who you paid or who paid you).
  • vendor — string (optional, for expense rows).
  • customer — string (optional, for income rows).
  • category — string (typically a Job name like "Spring Sports", or a bookkeeping bucket like "Cost of Goods Sold").
  • chartAccount — string (Chart of Accounts entry).
  • expenseIncome — string (Expense Table entry name; cross-references the COA).
  • jobNo — string (Job No. this tx is linked to).
  • account — string (which bank/cash account).
  • memo — string (optional note).
  • tags — array of strings.
  • reconciled — "" | "C" (cleared) | "R" (reconciled).

3.3 Special category constants

The app recognizes three named groups of categories:

4. Overview Page

The default landing page. Designed for at-a-glance financial health.

4.1 Year selector

A row of year pills at the top: All, every year with data, and a More ▾ drawer if you have more than ~6 years. Click a year to scope every chart and total on the page to that year. Locked years show a small red dot in the lower-right of the pill.

On mobile, year pills are replaced with a single dropdown that opens a sheet. The same red lock indicator appears on each year in the sheet.

4.2 Summary cards (the four colored tiles)

  • Income — total income for the selected year (or all years if "All").
  • Expense — total non-savings expense for the selected year.
  • Savings — net flow into savings categories (deposits − withdrawals).
  • Net — Income − Expense (excludes savings transfers).
Net = Σ(income.amount) − Σ(non-savings expense.amount)
Savings = Σ(savings expense.amount) − Σ(savings income.amount)

Roll Over / Correction categories are skipped in all four calculations to prevent double-counting carry-forward entries.

4.3 Year-over-year cards

When a specific year is selected (not "All"), four small YoY tiles appear showing the percentage change vs the same period in the prior year. For the current calendar year the comparison is YTD-to-YTD (e.g. Jan 1 → today's date in both years).

YoY % = ((current − prior) ÷ |prior|) × 100
Edge cases: prior = 0 → "—"; current > 0 → "+∞%"

4.4 Savings Goal thermometer

Vertical (desktop) or horizontal (mobile) progress bar comparing Savings YTD vs the goal set in Settings → Savings Goal. Fill width is (actual ÷ goal) × 100%, capped at 100%. When met, the bar label switches to "Goal met · $X over".

4.5 Open / Complete Jobs counters

Two small tiles count jobs in the selected year by status. A job counts as "Complete" when its status field equals "Paid"; otherwise it counts as "Open".

4.6 Total Income by Year chart

Vertical bar chart of yearly income with a 6-year sliding window (use ◂ ▸ buttons to scroll older). Above each bar, the year's income in dollars and a YoY % delta (green ▲ for up, red ▼ for down) appear.

Goal line: For the current calendar year only (and only when not in YTD-only mode), a dashed accent line marks the "goal" = average of the previous three years' income. Useful as an implicit revenue target.

4.7 Income by Job donut

Donut chart and per-category list of income contributors for the selected year. Categories without income that year are excluded. Clicking a slice or list row jumps to the Transactions tab filtered to that category × year.

4.8 Job / Category / Account summary tables

Three side-by-side tables at the bottom showing per-job income, per-category expense, and per-account balance — all scoped to the selected year. Each row sums to the four totals at the top.

7.6 New / Edit transaction modal

Fields and behavior:

  • Date — defaults to today.
  • Existing Job (Y/N) — toggle. When Y, a Job No. picker appears; selecting one auto-fills Customer + Category.
  • Customer — select dropdown with "+ Add new…".
  • Outflow / Inflow — mutually exclusive; typing in one clears the other. $0.00 is allowed.
  • Category — selectable list refreshes based on the chosen customer (cascade narrowing).
  • Payee — typed value, with autocomplete from state.payees (auto-grown on save).

7.7 Locked years

Any attempt to create, edit, or delete a transaction whose date falls in a locked year is blocked and a toast appears: "YYYY is locked in Settings". Swipe-delete, modal-delete, bulk-delete, inline-edit, and CSV import all enforce this.

7.8 Smart Vendor autofill (new — 2026-06)

Picking an existing vendor on a new transaction automatically prefills Category, Expense, Chart Account, Payee, and Account from that vendor's most recent expense transaction. The intent: typing "Adobe" or "Speedway" shouldn't make you re-pick the same five fields you always pair with that vendor.

Rules:

  • Only runs on new transactions. Opening an existing transaction for edit never triggers autofill.
  • Never clobbers a field you've already filled — autofill only writes into empty fields.
  • For <select> fields, it only writes a value that's actually one of the current options (prevents stale/orphaned strings).
  • Each filled field briefly glows blue (≈1.6s) so you can see what was prefilled and override anything that's wrong.
  • An info toast pops at the bottom: "Autofilled from last [vendor] entry".
  • Brand-new vendors added via "+ Add new…" have no history — autofill silently skips.

Source: the most-recent (not most-common) expense transaction for that vendor — matches the assumption that your current habits are more relevant than what you did three years ago.

7.9 Mobile swipe gestures (updated — 2026-06)

On mobile, the All Transactions list responds to two opposite swipe directions. Both run only when the 3-line stacked layout is active (the default mobile view).

Left-swipe → Edit / Delete panel

  • Drag a row to the left past about 60px to reveal two buttons: Edit (blue) opens the transaction modal; Delete (red) removes the row after a confirm.
  • Tap anywhere outside the row, or swipe a different row, to close the panel.
  • Locked-year transactions block Delete with the standard toast.

Right-swipe → Toggle Reconciled

  • Drag a row to the right. The row paints progressively greener as your finger moves.
  • Past the 80px threshold, the green deepens and a 4px green stripe pops on the left edge — that's the "release now to commit" signal.
  • Release past threshold: the row flips Reconciled (or un-flips if it was already reconciled), a centered ✓ (or ✕) pulse plays for ~700ms, then the list re-renders so the running balance updates.
  • Release before threshold: snaps back, nothing changes.
  • Locked years block the toggle with the standard toast before any mutation.

At-a-glance status indicator

Every reconciled row gets a thin green left border; rows in the intermediate Cleared state get an amber left border. Visible whether you swiped to reconcile or used the dot in the recon column.

Direction-locks on the first 10px of horizontal motion, so the two gestures never fight each other.

7.10 Paid jobs in the edit modal

The Job No. dropdown normally hides jobs whose status is Paid to keep the picker clean. When you open an existing transaction that's linked to a Paid job, that specific Paid job is still shown in the dropdown so its link doesn't silently disappear. (Bug fix · 2026-06.)

9. Analytics — Year Matrix

A Back arrow appears on the Transactions toolbar; clicking it returns you to the Year Matrix view. A "Drill: …" chip in the toolbar names the subset you drilled into.

The first column is locked at 155px so toggling Income/Expense doesn't change widths. Long names truncate with "…".

11. Analytics — Cash Flow

11.1 What it shows

Vertical bar chart with one bar per month for a single year. Each bar stacks income (green, going up from $0) and expense (red, going down from $0). A line overlay traces the running net (income − expense) at the end of each month.

11.2 Year selection

Cash Flow always renders ONE year. Year choice:

  1. If the universal Date Range filter has a selection → most recent of those years.
  2. Else, if the current calendar year has any data → current year.
  3. Else, the most recent year with any transaction data.

11.3 Toolbar

Flow / Trend mode switch — Flow shows the two-direction bars; Trend hides bars and shows only the net line.

11.4 Stats sidebar

Right side of the card on desktop, stacks below on mobile.

  • Net: total income − total expense for the year.
  • Avg: net ÷ months in the period.
  • Avg Out: expense total ÷ months.
  • Total In / Total Out.

11.5 Mobile

Month labels rotate 45° clockwise to prevent overlap; padding bumps accordingly. Y-axis ticks and month labels render at 20px (SVG units) for legibility.

12. Analytics — By Category

12.1 What it shows

Aggregate of either spending or income, grouped by Category, with four selectable chart styles.

12.2 Switches

  • Spending / Income — Total filters by transaction type.
  • Gross / Net — Gross sums |amount|; Net subtracts opposite-type amounts in the same category.
  • Donut / Columns / Treemap / Rose — chart style.

12.3 Donut chart

SVG donut. Each slice's label format is "Category 24%" on a single line, with the dollar amount on the sub-line beneath. Slices below 1.5% of total are aggregated into "Other".

12.4 Columns chart

Vertical bars in descending order. Each bar shows the dollar value; a small % above each bar shows that category's share of total. On mobile, x-axis category names rotate 45° to prevent overlap.

12.5 Treemap chart

Binary treemap — each rectangle's area is proportional to its category's share. Long names truncate with "…". Font size auto-scales based on cell area; mobile labels use a larger range (16–28 px in SVG units vs 11–20 on desktop).

12.6 Rose chart

Coxcomb / polar-area chart. Each wedge has equal angular width but radius is scaled by sqrt(value) so visual area ≈ value.

12.7 Sidebar tiles

  • Total, Avg / Month, Top Category (name + % share), Categories (count).

12B. Analytics — By Customer (Customer Profitability)

New in App v2 · 2026-06. Sits between By Category and Cash Flow in the Analytics pill nav. Universal filters apply.

12B.1 What it shows

Ranks every customer by Net (Gross − Direct Costs) so you can see at a glance which customers actually move the business. The card has three parts:

  • Header — big Net total (green if positive, red if negative) and a meta line: number of customers · number of jobs · total Gross · total Direct Costs.
  • Top-10 bar chart — horizontal bars, one per customer, sorted by Net. Click a bar to drill in.
  • Full table — every customer with: Customer · Jobs · Gross · Direct Costs · Net · Avg / Job. Sorted by Net descending. Click any row to drill in.

12B.2 How the numbers are computed

A transaction "belongs" to a customer if (a) its customer field is set directly, OR (b) it's linked to a jobNo whose job's customer is set. So both invoice-style income (where you tagged the customer) and older job-linked income (only jobNo set) both surface.

Gross = Σ income transactions belonging to that customer
Direct Costs = Σ expense transactions tagged to a job whose customer matches
Net = Gross − Direct Costs
Jobs = count of state.jobs whose customer matches (filtered by date-range)
Avg / Job = Net ÷ Jobs

Non-job overhead (rent, software, insurance — anything not linked to a specific job) is intentionally excluded from Direct Costs because it can't be fairly attributed to one customer. The Net figure is therefore a "contribution margin" per customer, not a fully- loaded profit.

Categories in NON_JOB_CATEGORIES (Roll Over, Correction) and SAVINGS_CATEGORIES are also excluded so they don't distort customer Net.

12B.3 Drill-down

Clicking a customer row or its bar in the chart jumps to the Transactions page filtered to every transaction belonging to that customer (direct or via job). A ‹ Back button appears on the Transactions toolbar; tapping it returns to the By Customer view.

12B.4 Mobile

  • The chart uses a narrower viewBox (600 SVG units wide) with bigger fonts so labels and value numbers read cleanly on a phone.
  • Customer names truncate at 16 characters (with "…") so they don't collide with the bar area.
  • The Avg / Job column is hidden in the table — five numeric columns are too noisy for phone width. Use the desktop view if you need that number.
  • The table's tfoot (Total row) is hidden on mobile because the same totals are already in the header meta line.

17. Analytics — Savings Rate

17.1 The headline rate

Savings Rate = Savings ÷ (Gross Profit − Job Expenses − Cost of Goods) × 100

Where:

  • Savings = Σ expense rows whose category OR expense-table entry is a savings category.
  • Gross Profit = Σ income rows (excluding Roll Over / Correction).
  • Job Expenses = Σ expense rows whose category is in JOB_ORDER.
  • Cost of Goods (CoGS) = Σ expense rows whose Chart Account matches "CoGS" / "Cost of Goods" (case-insensitive), OR whose category is literally "Cost of Goods" / "CoGS" for legacy data. CoGS takes precedence over Job Expenses — a Baseball-category expense with COA=CoGS is cost of goods, not a job expense. Updated 2026-06 so the Savings Rate view matches the Year-End report (was previously category-only, which missed CoGS classified via the COA column).

26. Cloud Sync & Backup

26.1 What's mirrored

The entire state object is serialized to JSON and pushed to Supabase as a single row keyed by your auth user_id. Every save triggers a debounced push.

26.2 Pull on sign-in

When you sign in, the app fetches the cloud row and overwrites local state with it. Useful when switching devices.

26.3 Safety guard

Before any push, if local state.transactions is empty AND the cloud row has transactions, the push is blocked. This prevents a fresh browser session from accidentally clearing your cloud data. The status indicator changes to "Empty local — push blocked" so you can investigate.

26.4 Manual recovery

If something goes wrong, paste this in the browser DevTools console while signed in to restore from the cloud: 

(async () => {
  const r = await supa.from("app_state_v2")
    .select("data")
    .eq("user_id", supaUser.id)
    .maybeSingle();
  localStorage.setItem("photo-bookkeeping-v1", JSON.stringify(r.data.data));
  location.reload();
})();

29. Formulas Reference

29.1 Transaction-level

signed amount = (type === "income" ? +1 : −1) × amount
linked to invoice = invoice exists whose jobNo === tx.jobNo
is savings = SAVINGS_CATEGORIES.includes(category OR expenseIncome)

29.2 Overview totals

Income = Σ amount where type === "income" AND !NON_JOB AND (no year filter OR date.startsWith(year))
Expense (display) = Σ expense.amount − Σ savings-expense.amount + Σ savings-income.amount
Savings (display) = Σ savings-expense.amount − Σ savings-income.amount
Net = Income − Expense (both as defined above)

29.3 Year-over-year

YoY % = ((current − prior) ÷ |prior|) × 100
YTD vs YTD comparison uses today's MM-DD as the cutoff for both years.

29.4 Savings Goal progress

fill % = clamp(0, savings_actual ÷ goal × 100, 100)
remaining = max(0, goal − savings_actual)

29.5 Goal line on Income by Year chart

goal = avg of the three prior calendar years' income totals
Hidden when selected year ≠ current calendar year OR YTD mode is on.

29.6 Job analytics

Job income = Σ tx.amount where tx.jobNo === job.jobNo AND tx.type === "income"
Job expenses = Σ tx.amount where tx.jobNo === job.jobNo AND tx.type === "expense"
Job profit = Job income − Job expenses

29.7 Cash Flow chart

For each month m:
  in[m] = Σ income.amount
  out[m] = Σ expense.amount
  net[m] = in[m] − out[m]
Cumulative net at month m = Σ net[0..m]

29.8 Savings Rate (per month and overall)

For each month m:
  profitBase[m] = income[m] − jobExpense[m] − cogs[m]
  rate[m] = profitBase[m] > 0 ? (sav[m] ÷ profitBase[m]) × 100 : 0

Overall (annual):
  Rate = totalSavings ÷ (totalIncome − totalJobExp − totalCogs) × 100

Ghost-bar rule: when sav[m] > 0 AND profitBase[m] ≤ 0, render a full-height faint bar instead of the percent.

29.9 Flow chart (per Job × Year)

posSum (Gross) = Σ income.amount per (year, job, payee) — RAW income, not netted
negSum = Σ signed-negative amounts per (year, job, payee)
net = posSum + negSum (signed sum)
grossTotal = Σ |amount| per (year, job)

29.10 By Category (Gross / Net)

Gross per category = Σ |amount| of wanted type
Net per category = Gross − Σ opposite-type amount in same category

29.11 Invoice math

line.amount = (parseFloat(line.qty) || 1) × parseMoneyInput(line.price)
subtotal = Σ line.amount
tax = mode === "tax" ? subtotal × (rate ÷ 100) : 0
total = subtotal + tax

29.12 Mileage

vehicleExpense = vehicleMiles × state.mileageRate
totalMiles for year = Σ trip.miles where trip.date startsWith year

29.13 Donut slice percentages

slicePct = (item.value ÷ total) × 100
Slices < 1.5% are bucketed into "Other" so labels don't crowd.

29.14 Treemap font size

labelFont = clamp(min, sqrt(cell.w × cell.h) ÷ divisor, max)
Desktop: min 11, max 20, divisor 9
Mobile: min 16, max 28, divisor 7

29.15 Job eligibility (Flow / Trends)

A category counts as a Job when:

  1. It exists in state.categories OR appears on any transaction.
  2. It's NOT in SAVINGS_CATEGORIES.
  3. It's NOT in NON_JOB_CATEGORIES.
  4. It has at least one income transaction.

29.16 Filter routing for categories

For any category value c:

  • If JOB_ORDER.includes(c) → routed through Job filter.
  • Else → routed through Category filter; but if Job filter is in restrictive Include mode and Category filter isn't, the row is excluded by default (matching "only show the chosen Jobs" intent).

31. Troubleshooting

31.1 "My data is gone"

Check the URL — make sure it's the production domain you usually use, not a Vercel preview URL with a different localStorage scope. If URL is correct, the data may still exist in the cloud row: open Settings → Cloud Sync, sign in, and click Force Download.

31.2 "It still looks the same after I changed a setting"

Hard-refresh the browser: Ctrl+Shift+R (Windows) or ⌘+Shift+R (Mac). Vercel sometimes serves a stale cached HTML that points to an older CSS / JS file.

31.3 "Why is the Savings Rate bar missing for a month I saved in?"

That month had no profit base (income ≤ Job Exp + COGS), so the rate formula's denominator was 0 or negative. The renderer shows a faint ghost bar at full height in those months to indicate savings happened without a defined rate.

31.4 "Only one Job shows up under All Jobs on Flow"

The Job filter on the universal Filters bar may be set to a single Job. Clear filters or check the chip in the toolbar. Otherwise, category eligibility requires at least one income transaction; check that the missing jobs have income on file.

31.5 "Force Download blocked by 'empty local'"

The push safety guard refuses to overwrite a non-empty cloud row with an empty local state. To force a recovery from the cloud, paste the manual restore script from §26.4 in DevTools.

31.6 "Locked year toast keeps blocking my edit"

Go to Settings → Locked Years and uncheck the year you want to edit. The transaction's date is what's checked, not today's date.

31.7 "Print doesn't include the toolbar (or it does, ugly)"

Use the Print / PDF buttons inside the report or invoice editor — they set the right @media print rules. Don't print via the browser File menu directly; that may include navigation chrome.
